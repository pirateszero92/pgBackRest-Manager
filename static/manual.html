📊 1. หน้า Stanzas & Backups (ดูสถานะและสั่ง Backup)

ความหมายของแต่ละคอลัมน์
  • Status (ok): เครื่อง DB เชื่อมต่อ MinIO และส่ง WAL ได้ปกติ
  • Latest Backup: ชุด Backup ล่าสุด (F = Full, D = Diff)
  • WAL Archive (Near-Realtime): แสดงเวลาล่าสุดที่ WAL ถูกส่งขึ้น MinIO (ส่งทุก ~60 วินาทีเมื่อมี transaction)
  • Recoverable Window: ช่วงเวลา เก่าสุด → ล่าสุด ที่สามารถย้อนเวลากู้คืน (PITR) ได้
ปุ่ม Actions ด้านขวา
  • Check — ตรวจสุขภาพ pgBackRest & MinIO (ไม่สร้างไฟล์ backup ใหม่)
  • Diff — สั่งทำ Differential Backup ทันที (แนะนำให้กดก่อน Deploy หรือก่อนแก้ข้อมูลใหญ่)
  • Full — สั่งทำ Full Backup ทันที (ปกติระบบรันอัตโนมัติทุกวันอาทิตย์ 02:00 น.)

🚨 5. Disaster Recovery: กรณี OS พังแล้ว Restore VM กลับมาจาก Backup

หาก OS พังแล้วกู้คืน VM/OS Backup (เช่น Proxmox/Veeam) กลับมา ข้อมูล PostgreSQL ใน VM นั้นจะเป็นข้อมูลเก่า ณ เวลาที่ Backup VM ไว้ — ให้ทำตามขั้นตอนนี้เพื่อดึงข้อมูลล่าสุด (รวมถึง WAL Archive ก่อนเครื่องพัง) จาก MinIO (10.1.1.211:9000) กลับมาให้ทันปัจจุบันที่สุด:

กรณี A: Restore VM Backup เดิมกลับมา (มี pgBackRest อยู่แล้ว)
  1. หยุด PostgreSQL บนเครื่องที่เพิ่งกู้คืน VM กลับมา: 
    sudo systemctl stop postgresql@16-main
  2. สั่ง Restore ข้อมูลล่าสุดจาก MinIO แบบ --delta (เปลี่ยน <STANZA> เช่น wms-prod, tms-prod, interface-prod, spp-prod, service-prod): 
    sudo -u postgres pgbackrest --stanza=<STANZA> --delta --type=default --target-timeline=latest --target-action=promote restore
  3. สตาร์ท PostgreSQL กลับมาและเช็กว่าพร้อมเขียนแล้ว (f): 
    sudo systemctl start postgresql@16-main
sudo -u postgres psql -tAc "SELECT pg_is_in_recovery();"
กรณี B: ลง OS + PostgreSQL 16 ใหม่ทั้งหมด (เครื่องเปล่า)
  1. ติดตั้ง Ubuntu + PostgreSQL 16 และติดตั้ง pgbackrest (2.60+ จาก PGDG Repo)
  2. สร้าง /etc/pgbackrest.conf (ชี้ MinIO 10.1.1.211:9000 และใส่ [<STANZA>] เดิม) และตั้งค่า /etc/postgresql/16/main/conf.d/99-pitr.conf
  3. หยุด PostgreSQL → รันคำสั่ง restore แบบเดียวกับกรณี A ข้อ 2 → สตาร์ท PostgreSQL กลับมา
💡 Tip: หลังกู้คืนเสร็จแล้ว แนะนำให้เช็กหน้า Stanzas & Backups และกดปุ่ม Check 1 ครั้ง เพื่อให้แน่ใจว่าเครื่องกลับมาส่ง WAL ขึ้น MinIO ต่อได้ตามปกติ (หากเป็นเครื่องที่มี Replica ให้ตรวจสอบ pg_stat_replication ด้วย)

🛠️ 6. ขั้นตอนติดตั้ง pgBackRest บนเครื่องใหม่ + Configuration ของทั้ง 5 Production Servers

เก็บไว้ใช้กรณีติดตั้งเครื่องใหม่ หรือ Reinstall OS + PostgreSQL 16 (Ubuntu 22.04 / 24.04)

Step 1: ติดตั้ง pgBackRest 2.60+ จาก PGDG Repo

⚠️ ห้ามใช้แพ็กเกจเริ่มต้นของ Ubuntu 22.04 (v2.37) เพราะไม่รองรับ PostgreSQL 16

sudo apt-get update
sudo apt-get install -y curl ca-certificates gnupg lsb-release
sudo install -d /usr/share/postgresql-common/pgdg
sudo curl -fsSL -o /usr/share/postgresql-common/pgdg/apt.postgresql.org.asc \
  https://www.postgresql.org/media/keys/ACCC4CF8.asc
echo "deb [signed-by=/usr/share/postgresql-common/pgdg/apt.postgresql.org.asc] \
  https://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" | \
  sudo tee /etc/apt/sources.list.d/pgdg.list
sudo apt-get update && sudo apt-get install -y pgbackrest
pgbackrest version
Step 2–4: ตั้งสิทธิ์ไฟล์ + Restore หรือเริ่ม Stanza ใหม่
# หลังวาง /etc/pgbackrest.conf และ 99-pitr.conf แล้ว:
sudo chmod 640 /etc/pgbackrest.conf
sudo chown root:postgres /etc/pgbackrest.conf

# ▶ กรณี Restore ข้อมูลเดิมกลับเข้าเครื่องใหม่:
sudo systemctl stop postgresql@16-main
sudo -u postgres pgbackrest --stanza=<STANZA> --delta --type=default \
  --target-timeline=latest --target-action=promote restore
sudo systemctl start postgresql@16-main

# ▶ กรณีสร้างเครื่องใหม่ (ยังไม่มี Backup ใน MinIO):

sudo -u postgres pgbackrest --stanza=<STANZA> check
sudo -u postgres pgbackrest --stanza=<STANZA> --type=full backup
